# GameService - Сервис логики игры

## Назначение и архитектура сервиса

GameService - это класс, реализующий паттерн Фасад для операций с игровыми сессиями в Telegram боте CashFlow. Сервис предоставляет высокоуровневый интерфейс для работы с играми, делегируя все операции с базой данных DatabaseService и статистикой UserStatsService.

Основные функции:
- Создание новых игровых сессий
- Начало игровых сессий
- Получение информации об играх
- Управление состоянием игр
- Обновление статистики пользователей

Архитектурно сервис:
- Является тонким слоем абстракции над DatabaseService и UserStatsService
- Делегирует CRUD операции DatabaseService
- Управляет статистикой через UserStatsService
- Сохраняет интерфейс для обратной совместимости с остальными компонентами
- Не содержит прямой работы с MongoDB

## Методы с их функционалом

### createGame(chatId, userId, username)
- **Назначение**: Создает новую игровую сессию
- **Параметры**:
  - `chatId` (string): ID чата
  - `userId` (string): ID пользователя-создателя игры
  - `username` (string): Имя пользователя
- **Возвращает**: Promise<string> - ID созданной игры
- **Функционал**:
  - Генерирует уникальный ID игры на основе timestamp
  - Генерирует случайную профессию для создателя
  - Создает объект игрока с начальными данными из профессии (все суммы в рублях по курсу 1$ = 30₽)
  - Инициализирует liabilities игрока кредитами профессии
  - Создает документ игры в базе данных с массивом players
  - Устанавливает статус 'waiting'

### joinGame(userId, gameId, username)
- **Назначение**: Присоединяет игрока к существующей игре
- **Параметры**:
  - `userId` (string): ID игрока
  - `gameId` (string): ID игры
  - `username` (string): Имя пользователя
- **Возвращает**: Promise<{success: boolean, error?: string, player?: Object}> - результат операции
- **Функционал**:
  - Проверяет существование игры
  - Проверяет, что игрок не уже присоединился
  - Проверяет, что статус игры 'waiting'
  - Генерирует случайную профессию для игрока
  - Создает объект игрока с начальными данными
  - Добавляет игрока в игру
  - Возвращает объект игрока в случае успеха

### startGame(userId, gameId)
- **Назначение**: Начинает игру (меняет статус на 'active')
- **Параметры**:
  - `userId` (string): ID пользователя (должен быть создателем)
  - `gameId` (string): ID игры
- **Возвращает**: Promise<{success: boolean, error?: string}> - результат операции
- **Функционал**:
  - Проверяет существование игры
  - Проверяет, что пользователь является создателем игры
  - Проверяет, что статус игры 'waiting'
  - Меняет статус на 'active' и добавляет время начала

### getGame(gameId)
- **Назначение**: Получает полную информацию об игре
- **Параметры**:
  - `gameId` (string): ID игры
- **Возвращает**: Promise<Object|null> - документ игры или null
- **Функционал**:
  - Возвращает все данные игры из базы данных
  - Используется для получения состояния игры

### getUserGames(userId)
- **Назначение**: Получает список активных игр пользователя
- **Параметры**:
  - `userId` (string): ID пользователя
- **Возвращает**: Promise<Array> - массив документов игр
- **Функционал**:
  - Находит все игры, где пользователь является участником
  - Фильтрует по статусам 'waiting' и 'active'
  - Возвращает полную информацию по каждой игре

### initiateEndGameVote(userId, gameId, messageId)
- **Назначение**: Инициирует голосование за окончание игры
- **Параметры**:
  - `userId` (string): ID пользователя
  - `gameId` (string): ID игры
  - `messageId` (number): ID сообщения голосования
- **Возвращает**: Promise<{success: boolean, error?: string}> - результат операции
- **Функционал**:
  - Проверяет существование игры и что она не завершена
  - Проверяет, что пользователь участник игры
  - Сохраняет массив голосов [userId] и messageId

### voteToEndGame(userId, gameId)
- **Назначение**: Голосует за окончание игры
- **Параметры**:
  - `userId` (string): ID пользователя
  - `gameId` (string): ID игры
- **Возвращает**: Promise<{success: boolean, error?: string, shouldFinish?: boolean}> - результат операции
- **Функционал**:
  - Проверяет существование игры и что она не завершена
  - Проверяет, что пользователь участник и не голосовал
  - Добавляет голос, проверяет majority (>50% игроков)

### finishGame(gameId)
- **Назначение**: Завершает игру
- **Параметры**:
  - `gameId` (string): ID игры
- **Возвращает**: Promise<{success: boolean, error?: string}> - результат операции
- **Функционал**:
  - Меняет статус на 'finished', добавляет время завершения

### setWaitingMessageId(gameId, messageId)
- **Назначение**: Устанавливает ID сообщения комнаты ожидания
- **Параметры**:
  - `gameId` (string): ID игры
  - `messageId` (number): ID сообщения
- **Возвращает**: Promise<{success: boolean, error?: string}> - результат операции
- **Функционал**:
  - Сохраняет ID сообщения комнаты ожидания для возможности его обновления или удаления

### rollDice(diceCount)
- **Назначение**: Бросает кубик(и) и возвращает сумму очков
- **Параметры**:
  - `diceCount` (number): Количество кубиков (1 или 2)
- **Возвращает**: number - Сумма выпавших очков
- **Функционал**:
  - Генерирует случайные числа от 1 до 6 для каждого кубика
  - Возвращает сумму результатов

### movePlayer(gameId, userId, steps)
- **Назначение**: Перемещает игрока на заданное количество полей и обрабатывает события на пройденных полях
- **Параметры**:
  - `gameId` (string): ID игры
  - `userId` (string): ID игрока
  - `steps` (number): Количество шагов
- **Возвращает**: Promise<{success: boolean, error?: string, newPosition?: number, fieldType?: string, inFastTrack?: boolean, paydayEvents?: Array<{position: number, cashFlow: number, newCash: number}>}> - результат операции
- **Функционал**:
  - Проходит по всем полям от текущей позиции до новой
  - Для каждого поля типа PAYDAY вызывает processPayday и собирает результаты в paydayEvents
  - Вычисляет новую позицию игрока с зацикливанием в текущем треке
  - Rat Race: зацикливание по 24 полям
  - Fast Track: зацикливание по 40 полям
  - Обновляет позицию в базе данных
  - Определяет тип поля, на которое попал игрок
  - Возвращает массив событий PAYDAY для отправки сообщений

### getCurrentPlayer(gameId)
- **Назначение**: Возвращает текущего игрока
- **Параметры**:
  - `gameId` (string): ID игры
- **Возвращает**: Promise<Object|null> - Текущий игрок или null
- **Функционал**:
  - Получает игру по ID
  - Возвращает игрока по индексу currentPlayerIndex

### nextTurn(gameId)
- **Назначение**: Передает ход следующему игроку
- **Параметры**:
  - `gameId` (string): ID игры
- **Возвращает**: Promise<{success: boolean, error?: string, nextPlayer?: Object}> - результат операции
- **Функционал**:
  - Переключает currentPlayerIndex на следующего игрока
  - Возвращает объект следующего игрока

### setCharityEffect(gameId, userId, effect, turnsLeft)
- **Назначение**: Устанавливает эффект благотворительности для игрока
- **Параметры**:
  - `gameId` (string): ID игры
  - `userId` (string): ID игрока
  - `effect` (boolean): Включить/выключить эффект
  - `turnsLeft` (number): Количество ходов (если effect = true)
- **Возвращает**: Promise<{success: boolean, error?: string}> - результат операции
- **Функционал**:
  - Устанавливает флаги charityEffect и charityTurnsLeft в базе данных

### decreaseCharityTurns(gameId, userId)
- **Назначение**: Уменьшает счетчик ходов благотворительности
- **Параметры**:
  - `gameId` (string): ID игры
  - `userId` (string): ID игрока
- **Возвращает**: Promise<{success: boolean, error?: string, turnsLeft?: number, effectEnded?: boolean}> - результат операции
- **Функционал**:
  - Уменьшает charityTurnsLeft на 1
  - Отключает эффект при достижении 0

### donateCharity(gameId, userId)
- **Назначение**: Обрабатывает пожертвование на благотворительность
- **Параметры**:
  - `gameId` (string): ID игры
  - `userId` (string): ID игрока
- **Возвращает**: Promise<{success: boolean, error?: string, donationAmount?: number, turnsLeft?: number}> - результат операции
- **Функционал**:
  - Рассчитывает доход игрока (salary + passiveIncome)
  - Вычисляет сумму пожертвования (10% от дохода)
  - Проверяет достаточность средств игрока
  - Списывает сумму пожертвования с баланса
  - Устанавливает charityEffect = true и charityTurnsLeft = 3
  - Возвращает ошибку 'insufficient_funds' при недостатке средств

### processPayday(gameId, userId)
- **Назначение**: Обрабатывает событие поля "День выплат" - начисляет месячный денежный поток и проверяет банкротство
- **Параметры**:
  - `gameId` (string): ID игры
  - `userId` (string): ID игрока
- **Возвращает**: Promise<{success: boolean, error?: string, cashFlow?: number, newCash?: number, bankruptcyTriggered?: boolean}> - результат операции
- **Функционал**:
  - Рассчитывает месячный денежный поток: salary + passiveIncome - totalExpenses
  - Добавляет/вычитает сумму к/из баланса игрока (cash)
  - Обновляет поле cashFlow в данных игрока
  - Проверяет условия банкротства: если cash < 0 и cashFlow < 0 и есть активы/долги
  - При банкротстве устанавливает bankruptcyState = true
  - Сохраняет изменения в базе данных

### buySmallDeal(gameId, userId, deal)
- **Назначение**: Покупает мелкую сделку (полная оплата наличными)
- **Параметры**:
  - `gameId` (string): ID игры
  - `userId` (string): ID игрока
  - `deal` (Object): Объект сделки с полями cost, passiveIncome, title, description
- **Возвращает**: Promise<{success: boolean, error?: string}> - результат операции
- **Функционал**:
  - Проверяет достаточность средств игрока (player.cash >= deal.cost, если cost указан)
  - Списывает полную стоимость с баланса игрока (если cost указан)
  - Использует passiveIncome или cashFlow как значение денежного потока для актива
  - Добавляет актив через databaseService.addAsset()
  - Возвращает ошибку 'insufficient_funds' при недостатке средств

### buyBigDeal(gameId, userId, deal)
- **Назначение**: Покупает крупную сделку (первоначальный взнос + кредит)
- **Параметры**:
  - `gameId` (string): ID игры
  - `userId` (string): ID игрока
  - `deal` (Object): Объект сделки
- **Возвращает**: Promise<{success: boolean, error?: string}> - результат операции
- **Функционал**:
  - Проверяет достаточность средств для первоначального взноса (player.cash >= deal.downPayment)
  - Списывает первоначальный взнос с баланса игрока
  - Рассчитывает сумму кредита (deal.cost - deal.downPayment)
  - Рассчитывает ежемесячный платеж (0.01% от стоимости)
  - Добавляет актив через databaseService.addAsset()
  - Добавляет кредит через databaseService.addLiability()
  - Возвращает ошибку 'insufficient_funds' при недостатке средств

### recalculateTotalExpenses(gameId, userId)
- **Назначение**: Пересчитывает общие расходы игрока при изменениях
- **Параметры**:
  - `gameId` (string): ID игры
  - `userId` (string): ID игрока
- **Возвращает**: Promise<{success: boolean, error?: string, totalExpenses?: number}> - результат операции
- **Функционал**:
  - Суммирует все расходы: expenses + childrenExpenses + totalLoanPayments
  - Обновляет поле totalExpenses в данных игрока
  - Сохраняет изменения в базе данных

## Бизнес-правила и проверки

### Правила создания игры
- Любая игра создается с уникальным ID
- Создатель автоматически становится первым игроком с случайной профессией
- Начальный статус всегда 'waiting'
- Сохраняется время создания игры
- После создания игры создателю отправляется карточка игрока с его данными

### Структура профессий
Профессии содержат следующие поля (все суммы в рублях по курсу 1$ = 30₽):
- `name`: Название профессии
- `salary`: Зарплата
- `passiveIncome`: Пассивный доход (всегда 0)
- `totalExpenses`: Общие расходы (включая кредиты)
- `cashFlow`: Денежный поток
- `savings`: Начальные сбережения
- `kidCost`: Расходы на детей по профессии
- `credits`: Массив кредитов с полями `title`, `cost`, `monthlyPayment`

Игрок получает начальные кредиты профессии как liabilities.

### Правила начала игры
- **Существование игры**: Игра с указанным ID должна существовать
- **Права создателя**: Только создатель игры может начать ее
- **Статус игры**: Начало возможно только для игр со статусом 'waiting'
- **Атомарность**: Все проверки выполняются перед модификацией данных

### Правила окончания игры
- **Менее 3 игроков**: /endgame сразу завершает игру без голосования
- **3 и более игроков**: /endgame инициирует голосование, требуется majority (>50% игроков)
- **Независимо от статуса**: Команда работает для игр в статусе 'waiting' или 'active'
- **Инициатор**: Автоматически голосует за завершение
- **Голосование**: Каждый игрок может голосовать один раз, сообщение обновляется в реальном времени

### Структура документа игры
Документ игры в MongoDB содержит следующие поля:
- `gameId`: Уникальный идентификатор игры (timestamp-based)
- `chatId`: ID чата, где создана игра
- `creatorId`: ID пользователя-создателя
- `players`: Массив объектов игроков
- `status`: Статус игры ('waiting', 'active', 'finished')
- `createdAt`: Время создания игры
- `startedAt`: Время начала игры (опционально)
- `finishedAt`: Время завершения игры (опционально)
- `endGameVotes`: Массив ID пользователей, проголосовавших за окончание
- `endGameMessageId`: ID сообщения голосования за окончание (опционально)
- `waitingMessageId`: ID сообщения комнаты ожидания (опционально)

### Статусы игр
- `waiting`: Игра ожидает дополнительных игроков
- `active`: Игра в процессе
- `finished`: Игра завершена по голосованию игроков или командой одиночного игрока

## Механика банкротства

### Условия банкротства
Игрок объявляется банкротом, если после дня выплат (PAYDAY):
- Баланс игрока отрицательный (`cash < 0`)
- Денежный поток отрицательный (`cashFlow < 0`)
- У игрока есть активы или кредиты для продажи/оплаты

Если активов и кредитов нет - немедленный проигрыш.

### Процесс банкротства
1. **Продажа активов**: Игрок продает активы за половину стоимости (`cost / 2`)
2. **Оплата кредитов**: После продажи всех активов оплачивает ежемесячные платежи по кредитам
3. **Проверка**: Повторяется до тех пор, пока `cashFlow >= 0`
4. **Результат**:
   - **Победа**: `cashFlow >= 0` - игрок выходит из банкротства и пропускает 3 хода
   - **Поражение**: После всех действий `cashFlow < 0` - игрок выбывает из игры

### Новые поля игрока
- `bankruptcyState` (boolean): Флаг состояния банкротства
- `skippedTurns` (number): Количество ходов для пропуска (0-3)

### Методы банкротства
#### sellAssetWithBankruptcy(gameId, userId, assetIndex)
- Продает актив по индексу за половину стоимости
- Обновляет баланс и денежный поток игрока

#### payLiability(gameId, userId, liabilityIndex)
- Оплачивает ежемесячный платеж по кредиту
- Удаляет кредит из списка liabilities

#### checkBankruptcyResolution(gameId, userId)
- Проверяет, достигнут ли положительный денежный поток

#### endBankruptcy(gameId, userId, isLoss)
- Завершает банкротство
- При победе: `skippedTurns = 3`
- При поражении: удаляет игрока из игры, обновляет статистику

### Интерфейс банкротства
- **Клавиатура**: Вместо "Бросить кубик" показываются "Активы" и "Кредиты"
- **Активы**: Кнопки "Продать [название] за [цена]" (цена = cost/2)
- **Кредиты**: Кнопки "Оплатить [название] за [цена]" (цена = monthlyPayment)
- **Пагинация**: По 5 элементов на страницу с кнопками "Назад"/"Вперед"

### Обработка ошибок
- Все методы возвращают Promise для поддержки асинхронности
- startGame возвращает объект с success/error для детального контроля ошибок
- Ошибки валидации возвращают специфические коды ('not_found', 'not_creator', 'already_started')
- База данных ошибки пробрасываются выше для централизованной обработки
