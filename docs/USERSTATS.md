# UserStatsService - Сервис статистики пользователей

## Назначение и архитектура сервиса

UserStatsService - класс, отвечающий за работу со статистикой пользователей в Telegram боте CashFlow. Сервис предоставляет:

- Создание и получение статистики пользователей
- Обновление статистики после завершения игр
- Форматирование статистики для отображения

Архитектурно сервис:
- Принимает экземпляр DatabaseService в конструкторе
- Предоставляет асинхронные методы для всех операций
- Использует коллекцию 'userStats' в MongoDB
- Возвращает структурированные результаты операций

## Методы с их функционалом

### constructor(databaseService)
- **Назначение**: Инициализация сервиса
- **Параметры**:
  - `databaseService` (DatabaseService): Экземпляр сервиса базы данных
- **Функционал**: Сохраняет ссылку на databaseService для работы с коллекцией 'userStats'

### getUserStats(userId)
- **Назначение**: Получает статистику пользователя по ID
- **Параметры**:
  - `userId` (string): ID пользователя Telegram
- **Возвращает**: Promise<Object|null> - объект статистики или null
- **Функционал**: Ищет документ в коллекции 'userStats' по userId

### createUserStats(userId, username)
- **Назначение**: Создает новую запись статистики для пользователя
- **Параметры**:
  - `userId` (string): ID пользователя Telegram
  - `username` (string): Имя пользователя
- **Возвращает**: Promise<Object> - созданный объект статистики
- **Функционал**:
  - Создает объект с начальными данными (totalGames: 0, wins: 0, losses: 0)
  - Добавляет timestamps createdAt и updatedAt
  - Вставляет документ в коллекцию 'userStats'

### updateUserStats(userId, updates)
- **Назначение**: Обновляет статистику пользователя
- **Параметры**:
  - `userId` (string): ID пользователя Telegram
  - `updates` (Object): Объект с обновлениями { totalGames?, wins?, losses?, username? }
- **Возвращает**: Promise<Object> - обновленный объект статистики
- **Функционал**:
  - Обновляет документ с помощью $set
  - Добавляет updatedAt timestamp
  - Использует upsert для создания записи, если не существует

### getOrCreateUserStats(userId, username)
- **Назначение**: Получает существующую статистику или создает новую
- **Параметры**:
  - `userId` (string): ID пользователя Telegram
  - `username` (string): Имя пользователя
- **Возвращает**: Promise<Object> - объект статистики
- **Функционал**:
  - Проверяет существование статистики
  - Создает новую, если не найдена
  - Обновляет username, если он изменился

### updateStatsAfterGame(game)
- **Назначение**: Обновляет статистику всех игроков после завершения игры
- **Параметры**:
  - `game` (Object): Объект завершенной игры
- **Возвращает**: Promise<void>
- **Функционал**:
  - Для каждого игрока в игре:
    - Получает или создает статистику
    - Увеличивает totalGames на 1
    - Пока устанавливает wins и losses в 0 (логика побед добавится позже)

### formatUserStats(stats) [static]
- **Назначение**: Форматирует статистику для отображения
- **Параметры**:
  - `stats` (Object): Объект статистики
- **Возвращает**: string - отформатированная строка
- **Функционал**:
  - Возвращает строку с количеством игр и процентом побед
  - Специальная обработка для пользователей без игр

## Структура данных

### Документ статистики пользователя (коллекция 'userStats')
```javascript
{
  userId: "string",     // ID пользователя Telegram
  username: "string",   // Имя пользователя
  totalGames: number,   // Общее количество сыгранных игр
  wins: number,         // Количество побед
  losses: number,       // Количество поражений
  createdAt: Date,      // Дата создания записи
  updatedAt: Date       // Дата последнего обновления
}
```

## Бизнес-правила и проверки

### Правила создания статистики
- Новая статистика создается при первом взаимодействии пользователя
- Начальные значения: все счетчики равны 0
- Сохраняются timestamps создания и обновления

### Правила обновления статистики
- Username обновляется при изменении
- totalGames увеличивается после каждой завершенной игры
- wins и losses пока не используются (резервировано для будущей логики)

### Обработка ошибок
- Все методы асинхронны и возвращают Promise
- Ошибки подключения к БД пробрасываются выше
- Валидация входных параметров не производится (делегируется вызывающему коду)

## Архитектурные принципы

- **Единственная ответственность**: UserStatsService отвечает только за статистику пользователей
- **Независимость**: Не зависит от других сервисов кроме DatabaseService
- **Расширяемость**: Легко добавить новые поля статистики
- **Производительность**: Использует индексы MongoDB для быстрого поиска
- **Безопасность**: Проверки на существование пользователя перед обновлением
